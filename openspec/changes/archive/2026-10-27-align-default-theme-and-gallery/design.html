Context

See proposal.md for the problem and scope. The current gallery plan emits family lists and separate light/dark figures; the host adds the shared shell. Source artifacts are currently download links. The shared CSS supplies warm gold defaults.

Smithy reference: site/public/styles.css at b97203c. The reference matches GitHub main as checked on 2026-10-27. Telescope source baseline is PR6 head 7eaa03b, whose tree equals merged main 215bc8c. Retain or update NOTICE if CSS is adapted.

Goals and non-goals

The shared toolkit owns color defaults and a reusable specimen browser. Consumer manifests and artifact files remain the source of gallery content. New controls enhance static HTML. A full client application, source editor, renderer service and new theme configuration API are outside this design.

Visual direction

A family rail and preview card grid make visual browsing the first action. Cards use consistent frames, restrained borders and indigo selection. On narrow screens the rail becomes wrapping family links above a single-column grid. Below are illustrative layouts, not generated diagram output.

Detail pages keep the family context, title and scope, then a large bounded specimen panel. Preview and Source controls occupy its top edge. SVG downloads, source downloads and an optional Open offline player link remain explicit actions. Source is inspectable without opening a new page.

Interaction references: shadcn blocks for preview/source presentation and Storybook browsing for family navigation. No code, dependency or full workbench is copied from either.

Decisions

The owner asked for the Smithy palette in Telescope and diagrams.mbt. Map the existing CSS variable names to the reference values below. Keep dark/system selectors equivalent and apply the explicit stored choice before the stylesheet. Retain the current font stack and avoid external fonts.

Call: distinguish subtle decorative separators from meaningful control boundaries. Use a stronger neutral control-border token and the accent focus ring where contrast requires it. Measure actual rendered text and interactive states. Keep status colors semantic and do not map warnings to the brand color. Do not recolor consumer SVG or player artifacts.

GAL-1. Call: static cards and family anchors

Update pkgs/telescope/gallery/plan.mbt and shared CSS. Keep manifest version 1, existing IDs, order, family IDs based on the first entry, detail routes and copy paths. Render grouped card lists in the base HTML so existing family hash links work without JavaScript. Available dark variants follow explicit and system themes. Fit images with contain semantics and let detail previews scroll internally when necessary. Single-theme SVGs use a compatible fixed preview surface.

A document list was rejected because it hides the primary output. A full Storybook runtime was rejected because this toolkit consumes checked static artifacts.

GAL-2. Call: small gallery enhancements

Add gallery behavior beside the existing islands, initialized only at gallery mounts. Family links remain real fragment links. With JavaScript, selecting a family also filters cards. Text matches title, family and description case-insensitively. Hide empty groups, announce the result count politely, retain focus in the active control and provide reset. Direct family hashes initialize the selected family; back/forward hash changes update selection. Without scripting, all cards and family sections remain visible and enhancement-only controls do not appear.

SRC-1. Call: host-read source, pure rendering

The host already verifies each artifact through realpath containment before output. Read supported UTF-8 text sources there, then provide their text as an optional explicit map to the pure gallery planner. Preserve existing two-argument planner calls with a defaulted optional parameter; do not add file I/O to the pure gallery package or alter manifest fields. Pure planner callers without source text retain source download links. Host builds provide inline source panels and escape source text as text, never HTML. Unsupported or non-UTF-8 sources remain labeled downloads.

Render all available text sources into the static detail page. Enhance Preview/Source into accessible tabs with roving focus and arrow/Home/End navigation. With no script, show preview and source sections together. Copy uses the source text and gives success or fallback feedback. Downloads keep exact bytes through the existing copy plan. Opening a player remains a separate navigation action, so gallery browsing never runs a player or renderer.

Browser-time source fetching was rejected because it loses no-script inspection and adds loading states. Public Entry fields remain unchanged. Record any generated interface change caused by the optional planner input.

REL-1. Call: release before consumer adoption

Qualify a clean packaged consumer first, then complete palette, gallery and accessibility checks. Update embedded CLI assets through the existing packaging task. Prepare the next release as a separate owner-reviewed version and commit; do not assume a version is published. After Actions publication, test actual public library and CLI installs on Linux x64 and macOS arm64 and send the version, source revision, archive URLs and checksums to the diagrams workspace. The downstream change remains on 0.1.1 until that evidence exists.

Verification

Run strict OpenSpec validation, format, setup and engine checks. Extend focused gallery-plan and host tests for source escaping, optional text input, byte-preserving copies and existing path validation. Use real browser checks for palette tokens and contrast, themes, keyboard tabs, filtering, empty state, hash navigation, clipboard denial, no JavaScript and widths 360, 768 and 1440. Exercise a no-gallery consumer and both root and project base paths. Run existing packaged and then published consumer qualification; do not replace public installs with a sibling source path.

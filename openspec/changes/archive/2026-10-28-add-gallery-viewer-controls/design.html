Add gallery viewer controls

Approved upstream implementation scope, 2026-10-28

Context · Goals · Decisions · Risks · Migration

Context

See proposal. Telescope 0.3.0 owns gallery markup and browser islands. Supplied SVG and source artifacts are copied unchanged. Cards currently wrap previews in their detail link.

Goals and non-goals

Keep the existing pure planning and native host boundary. Consumer raster code stays in supplied local assets. No diagram engine, browser canvas substitute or publication is part of this implementation.

Decisions

VIEW-1. Owner: scoped shared viewport contract

Use the diagram-viewer root and part classes and CSS variables agreed with diagrams.mbt. Copy reviewed framework-free viewport assets into Telescope. Move preview markup outside card navigation; retain a title link and stable routes. The runtime adds controls only after script runs. Transform content beneath a fixed toolbar, with native fullscreen and in-place modal fallback.

RASTER-1. Call: explicit consumer adapter

A local configured adapter script registers window.DiagramsRaster.export. Its asynchronous input contains canonical SVG, format, validated options, AbortSignal and progress callback; its result has bytes, mediaType, width and height. Telescope fetches canonical SVG only when export starts, reports errors and supplies download feedback. It never captures transformed DOM.

BRAND-1. Call: optional shell asset paths

Two optional configuration strings identify output paths for logo and favicon. Existing static mapping copies the files. Validation rejects absolute, traversal and ambiguous URL paths. Shell URLs use config.href so assembly retains each version context.

Risks and trade-offs

Fullscreen can lose inherited tokens. Keep the viewer within its existing root and test custom properties. Dragging can steal link clicks. Keep controls outside links and require a drag threshold. Adapter failure must not affect source actions. Use per-export exception handling and byte checks.

Migration plan

Package the implementation and test an independent consumer. Land this implementation only after checks and review. Prepare evidence for a separate owner-approved matching library and CLI release before downstream adoption. Rollback restores previous generic assets and optional configuration.

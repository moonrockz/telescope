Context

See the proposal. Moon-Lander PR 138 consumes the released host on Windows. Native canonical paths contain backslashes and extended drive or UNC prefixes. Slash-only containment rejects valid children; temporary staging can mistake a whole Windows path for a filename.

Goals and non-goals

Fix native filesystem boundaries without changing public signatures, source-relative syntax or site URLs. Windows CLI binary distribution is outside this fix; existing Linux/macOS archives remain qualified separately.

Decisions

PTH-1. Call: normalize canonical filesystem paths once

Route host canonicalization through one native boundary helper. On Windows, convert drive and UNC paths, including extended prefixes, to the slash representation used for containment and joins. Preserve POSIX paths literally. Normalize raw native output paths before deriving parent and basename. Keep relative authored paths strict. Do not weaken containment or replace the shared host in consumers.

CI-1. Call: qualify the Windows library host on an actual runner

Add one reusable Windows host job to PR and release workflows. It runs strict native compilation and host fixtures. Publication depends on that result and both existing artifact qualifiers. A cross-built executable cannot prove Windows filesystem behavior. Prepared-package consumers on existing platforms retain the independent-install gate.

REL-1. Owner: publish only after exact release approval

Prepare a patch release after the fix qualifies. Publication stays in GitHub Actions and needs owner approval of the concrete source/version. Moon-Lander pins only that actual published package, then reruns its Windows and site checks.

Risks and trade-offs

Path normalization can weaken boundaries: test sibling prefixes, other drives, UNC shares and resolved escapes. POSIX backslashes can be real filename characters: normalize only Windows paths. Windows host coverage adds a distinct OS check; no existing matrix or permission is removed. Canonical input must not be confused with a URL or authored relative path.

Migration plan

Implement and qualify the shared fix, merge it, prepare the versioned release and request exact publication approval. After actual publication, update Moon-Lander's pin and validate its existing consumer. Roll back by retaining the prior pin and keeping adoption blocked; never replace a published archive.

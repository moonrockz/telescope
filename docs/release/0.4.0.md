# Telescope 0.4.0 candidate

This is an unpublished local release candidate. No release PR, GitHub release or
Mooncakes publication has been created for it. The last published version is
[0.3.0](0.3.0.md).

## Included implementation

[PR 15](https://github.com/moonrockz/telescope/pull/15) merged as
`b51ebf8c9aa2a9cd5ba2b029b6fd374574c73cec`. Its validated source was
`94c8ee3f5cedf20854fc300a7df469bda6122008`; the merge tree matches that source.
[Linux x64 and macOS arm64 CI](https://github.com/moonrockz/telescope/actions/runs/40757554870)
passed packaging and fresh independent consumers. Linux also passed 118 browser
tests. Both verified theme review findings are fixed and resolved.

The release adds gallery fullscreen, zoom, pan and Fit controls, stable viewer
styling and theme hooks, optional header/favicon assets, and a consumer-owned
local PNG/JPEG adapter contract. Source and static SVG bytes remain unchanged.
The candidate also fixes modal fullscreen scroll restoration near the page bottom, with a browser regression.
Telescope does not implement diagrams raster conversion. Consumers must supply
and qualify their own converter.

## Migration

JSON configuration remains compatible. New optional output paths are
`header_logo`, `favicon` and `gallery_raster_adapter`. Missing or empty strings
retain the existing text brand and SVG actions.

Direct public `SiteConfig` struct literals must add these three string fields.
Use empty strings to retain prior behavior. This source compatibility change is
why the candidate advances from 0.3.0 to 0.4.0.

The library and CLI, fixture imports, archive names, release version checks and
manual workflow default select 0.4.0 together. No toolchain dependency changes
are part of this candidate.

## Qualification and approval

Candidate qualification uses `moon package` and an isolated explicit prerelease
cache for independent consumers. These are test inputs, not published
coordinates. Local commands are:

```sh
RELEASE_VERSION=0.4.0 mise exec -- moonx scripts/release-version.mbtx
mise run format
mise run check:setup
mise run check
mise run package
mise run test:publish-environment
mise run test:consumer -- --prepared
mise run test:browser
```

The publication dry run requires an Actions-only credential and the exact-source
owner/admin gate. It is not run on a workstation. No dummy credential is created.
After approval, the release PR must pass CI on both native platforms. A separate
manual owner/admin dispatch must identify its actual merge commit and version
before publication can run through `.github/workflows/release.yml`.

Adoption stays blocked until `moonrockz/telescope@0.4.0` and matching native CLI
archives actually exist, checksums verify, and fresh published Linux/macOS
consumers pass without a candidate cache or workspace override.

## Local candidate result

The local macOS arm64 0.4.0 candidate passed the version check, format, setup and
strict spec checks, 284 native tests and pure four-target checks. Its stock CLI
reports 0.4.0. Packaging produced the matching library ZIP and native archive;
the archive checksum verified. The credential-free publisher-environment test
passed both cases. An independent prepared consumer installed
`moonrockz/telescope@0.4.0` from an explicitly seeded candidate cache, with no
workspace override or credential, and passed root and project-base builds.
The 120 browser tests passed, including near-bottom modal scroll restoration.

These local results do not claim Linux qualification or public availability for
0.4.0. Linux/macOS CI for this version will run after owner approval to open the
release PR. Actual publication and public-install evidence remain outstanding.

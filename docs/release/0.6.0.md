# Telescope 0.6.0

The library is published as `moonrockz/telescope@0.6.0` on
[Mooncakes](https://mooncakes.io/docs/moonrockz/telescope), with a
[matching CLI release](https://github.com/moonrockz/telescope/releases/tag/v0.6.0).
Owner-approved [Actions run 42413714875](https://github.com/moonrockz/telescope/actions/runs/42413714875)
published exact source `3bc7acf1a050188ecbe5ba06e3d024af4a54b18d` after
[release PR 26](https://github.com/moonrockz/telescope/pull/26). The tag points
to that source. The live owner/admin gate checked the exact commit, version,
event inputs and merged release PR before upload. Mooncakes lists `0.6.0` as the
latest version.

## Toolchain and compatibility

The minimum toolchain is now MoonBit `0.10.20+65efd5b93` (moon `0.1.20261104`),
from [PR 25](https://github.com/moonrockz/telescope/pull/25). MoonBit 0.10.18 and
older are not supported: the source uses the `#derive(...)` attribute, and `Json`
comes from `moonbitlang/core/json`. The supported `moon doc` format is the 0.10.20
format. It has the same shape as before; only the `Json`, `ToJson` and `FromJson`
links move from `moonbitlang/core/builtin` to `moonbitlang/core/json`.

The public interfaces show `@json.Json` where they showed `Json`. This is the same
type, so source that uses these functions does not change. Consumers must build
with MoonBit 0.10.20 or later. That is why this release is a minor version.

`moonrockz/telescope` keeps `moonbitlang/async` 0.22.5, because its pure packages
build on wasm-gc. Manifest version 1 and the public plan signature stay
compatible. The CLI distributions remain Linux x64 and macOS arm64; no Windows
CLI archive is claimed.

## Fixes

- **Browser islands on MoonBit 0.10.20.** On the js target, a MoonBit `Array` is
  no longer a raw JavaScript array. The search island and the version switcher
  received JavaScript arrays as `Array`, so with 0.10.20 the search index and the
  version list did not load. They now receive `FixedArray` and change it to
  `Array` in MoonBit. Sites that build their islands with 0.10.20 must use this
  release.
- **Cleanup on cancellation.** The native host protects its staging cleanup and
  output rollback from cancellation with `@async.protect_from_cancel`.

## Qualification and public consumers

The release repeated qualification on the exact approved source. The Windows
host job, the Linux x64 and macOS arm64 qualifiers and the credential preflight
passed. Linux passed all 124 browser cases.

The credential-dependent dry run, library upload, matching CLI publication and
Linux public consumer succeeded in the Actions publication job. A separate
macOS public consumer also passed:

```sh
mise run test:consumer -- --published 0.6.0
```

Both consumers started from empty public registry homes, installed the real
Mooncakes package and downloaded checksum-verified CLI archives. They used no
candidate cache, workspace/path override or consumer credential. Checks cover
host/CLI builds at root and nested bases, artifact bytes, custom providers,
API metadata, preview, failed-build preservation, deterministic output,
standalone editor/Formatter and seven tutorial cases with native/worker parity.

# Telescope 0.6.0 candidate

This minor release prepares the MoonBit 0.10.20 upgrade from
[PR 25](https://github.com/moonrockz/telescope/pull/25), merged as
`68db9b0588a0b9be37dcbbb1358512c395e82836`.
The package and matching CLI candidate version are `0.6.0`.
Publication has not occurred. Consumers keep their existing pin until the owner
approves the concrete release and actual public qualification passes.

## Toolchain and compatibility

The minimum toolchain is now MoonBit `0.10.20+65efd5b93` (moon `0.1.20261104`).
MoonBit 0.10.18 and older are not supported: the source uses the `#derive(...)`
attribute, and `Json` comes from `moonbitlang/core/json`. The supported
`moon doc` format is the 0.10.20 format. It has the same shape as before; only the
`Json`, `ToJson` and `FromJson` links move from `moonbitlang/core/builtin` to
`moonbitlang/core/json`.

The public interfaces show `@json.Json` where they showed `Json`. This is the same
type, so source that uses these functions does not change. Consumers must build
with MoonBit 0.10.20 or later. That is why this release is a minor version.

`moonrockz/telescope` keeps `moonbitlang/async` 0.22.5, because its pure packages
build on wasm-gc. Manifest version 1 and the public plan signature stay
compatible.

## Fixes

- **Browser islands on MoonBit 0.10.20.** On the js target, a MoonBit `Array` is
  no longer a raw JavaScript array. The search island and the version switcher
  received JavaScript arrays as `Array`, so with 0.10.20 the search index and the
  version list did not load. They now receive `FixedArray` and change it to
  `Array` in MoonBit. Sites that build their islands with 0.10.20 must use this
  release.
- **Cleanup on cancellation.** The native host protects its staging cleanup and
  output rollback from cancellation with `@async.protect_from_cancel`.

prerelease cache, not a published package.

The release-version change must pass those same jobs before promotion. Record
its exact merged source SHA and release PR when they exist. The manual release
workflow must run qualification on that exact source before any upload.

## Publication gate

The owner must approve the exact release source and version. Publication runs
only through the manual GitHub Actions release workflow. Its approval gate checks
the owner/admin actor, matching event inputs and the merged release PR SHA.
The publication job requires the Windows host check, both distribution qualifiers
and the credential preflight. No workstation publication is permitted.

Expected artifacts after approval are `moonrockz/telescope@0.6.0`, matching
`telescope-0.6.0-linux-x64.tar.gz` and `telescope-0.6.0-macos-arm64.tar.gz`, and their
download checksums. These names are planned coordinates, not publication receipts.
No Windows CLI archive is claimed.

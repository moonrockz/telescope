# Telescope 0.1.1

The library is published as `moonrockz/telescope@0.1.1` on
[Mooncakes](https://mooncakes.io/docs/moonrockz/telescope).
The [matching CLI release](https://github.com/moonrockz/telescope/releases/tag/v0.1.1)
was published by [Actions run 40531421002](https://github.com/moonrockz/telescope/actions/runs/40531421002)
from source `4c2c7ebb235425c917780fccfc874a5beb06c156`, after owner-approved
[PR 5](https://github.com/moonrockz/telescope/pull/5) merged.

## Install

Pin the library in a native consumer's `moon.mod`:

```moonbit
import {
  "moonrockz/telescope@0.1.1",
}
preferred_target = "native"
```

Run `moon update` to initialize a new public registry, then build the consumer
with MoonBit `0.10.17+093cb8f9c`. Import the needed public packages in `moon.pkg`,
such as `moonrockz/telescope/host` and `moonrockz/telescope/extensions`.

Download the archive and its `.sha256` companion for your platform:

| Platform | Archive | SHA-256 |
| --- | --- | --- |
| Linux x64 | [telescope-0.1.1-linux-x64.tar.gz](https://github.com/moonrockz/telescope/releases/download/v0.1.1/telescope-0.1.1-linux-x64.tar.gz) | `dbd2e1813b6d1a7d16bf88e022cd5e971209811fc12c2cf3c7955d6270dca4de` |
| macOS arm64 | [telescope-0.1.1-macos-arm64.tar.gz](https://github.com/moonrockz/telescope/releases/download/v0.1.1/telescope-0.1.1-macos-arm64.tar.gz) | `10fc718ff86184a8d21cb77aec0dfff3ad35c16008d8de0b5bbd272a274a1036` |

For example, on macOS arm64:

```sh
curl --fail --location --remote-name https://github.com/moonrockz/telescope/releases/download/v0.1.1/telescope-0.1.1-macos-arm64.tar.gz
curl --fail --location --remote-name https://github.com/moonrockz/telescope/releases/download/v0.1.1/telescope-0.1.1-macos-arm64.tar.gz.sha256
shasum -a 256 -c telescope-0.1.1-macos-arm64.tar.gz.sha256
tar -xzf telescope-0.1.1-macos-arm64.tar.gz
./telescope-0.1.1-macos-arm64/telescope --version
```

The last command prints `0.1.1`. Extracted CLI binaries contain CSS and browser
islands and need no Telescope checkout or MoonBit compiler. A compiled consumer
with custom providers needs the pinned MoonBit toolchain. Other native platforms
are not qualified by this release.

## Compatibility

Library and CLI versions are both `0.1.1`. Configuration, extension-adapter and
gallery-manifest contracts are version `1`. MoonBit API ingestion is qualified
against compiler `0.10.17+093cb8f9c`. Pure model/content/gallery/extensions packages
check on wasm, wasm-gc, JS and native; CommonMark, Rabbita views and filesystem
hosting use native packages. Browser islands use JS.

Use the released [public library API](https://github.com/moonrockz/telescope/blob/4c2c7ebb235425c917780fccfc874a5beb06c156/pkgs/telescope/README.md),
[native host](https://github.com/moonrockz/telescope/blob/4c2c7ebb235425c917780fccfc874a5beb06c156/pkgs/telescope/host/README.md),
[provider contract](https://github.com/moonrockz/telescope/blob/4c2c7ebb235425c917780fccfc874a5beb06c156/pkgs/telescope/extensions/README.md),
[gallery contract](https://github.com/moonrockz/telescope/blob/4c2c7ebb235425c917780fccfc874a5beb06c156/pkgs/telescope/gallery/README.md) and
[CLI configuration](https://github.com/moonrockz/telescope/blob/4c2c7ebb235425c917780fccfc874a5beb06c156/docs/cli.md). Consumers compile their own renderer providers
and own gallery artifact generation, release selection and deployment. Telescope
contains no diagram engine and does not fetch historical releases during assembly.

## Published qualification

The release job installed from the actual public registry and GitHub downloads
on Linux x64. The coordinator repeated the same command on macOS arm64:

```sh
mise run test:consumer -- --published 0.1.1
```

Both passed with empty registry homes and no candidate entry, local path or
workspace override. They verified the exact dependency and CLI version, archive
checksum, compiled custom fence provider, deterministic builds and checks at `/`
and `/example/`, failed-build preservation, API generation and preview shutdown.
Retained reports are [Linux](consumer-0.1.1-linux-x64.json) and
[macOS](consumer-0.1.1-macos-arm64.json).

The same release passed 224 native engine tests, two owner-gate tests, two
publisher regressions and the fresh-public-index regression on both platforms,
plus 42 Linux browser checks. The separate actual-diagrams source fixture
preserved 77 routes, 5,376 anchors and 40 gallery artifact bytes across supplied
version trees. That source fixture complements the real published-consumer
qualification; diagrams adoption has its own integration checks.

## Changes since 0.1.0

The enabled gallery appears in the shared primary navigation, with the correct
current-page link. Its index groups examples by family, details link back to
their family, and light/dark SVG previews have explicit download links. These
links work without JavaScript and stay inside the active version tree.

Supplied-tree assembly adds a latest-page canonical link when `site_url` is
provided and the latest release contains that page. It preserves authored
canonicals, leaves next-only and removed pages without invented latest links,
and keeps standalone filenames such as `genindex.html` intact. Consumers keep
owning release selection and historical asset downloads.

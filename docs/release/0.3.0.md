# Telescope 0.3.0 candidate

0.3.0 is prepared for owner review. It has not been published. The exact release
commit is the implementation PR's authoritative squash merge SHA, reported with
its URL after merge. An open PR head, local package or candidate cache does not
authorize publication or downstream adoption.

This release adds optional TOML tutorial manifests, stable course/lesson routes,
static reading and tested source includes, consumer-owned local execution,
case/evidence checking, comparison and stepping. The reusable editor and public
Formatter belong to `moonrockz/telescope/editor` and require no tutorial setup.
Its optional rich adapter ships MoonBit highlighting selected by `moonbit` or
`mbt`, without a compiler or formatter requirement.

Existing site JSON, version-one extension registries and host calls remain
source compatible. Tutorial inputs are optional and separately decoded. Authored
tutorials use TOML schema version 1; runtime envelopes, expectations and reports
use JSON. Provider and formatter protocols start at contract version 1. Consumers
ship prebuilt assets and compile their own evaluator/formatter implementations.
Builds validate/render without executing an engine. Case checking is a separate
host API and consumer-driver operation.

See [authoring](../tutorials.md), [general editor](../editor.md),
[provider contracts](../tutorial-contracts.md) and the
[verification/parity matrix](../tutorial-verification.md).

Local macOS arm64 [candidate evidence](candidate-0.3.0-macos-arm64.json)
records the exact qualified archive hashes and explicitly unpublished cache
provenance. The independent consumer passes standalone Formatter, native/worker
protocol and revision parity, seven cases, custom editor/language registrations,
both deployment bases, actual Chromium edits and repeated-byte checks. Existing
gallery, version-one provider and preview checks also pass. Publisher-home and
fresh public-index bootstrap tests pass without a publication credential.

Both supported platforms pass [candidate CI](https://github.com/moonrockz/telescope/actions/runs/40635105037)
for source `e8081e929f56831a26d78b8a928c247dbe2fb6b2`. The
[CI evidence](candidate-0.3.0-ci.json) retains each candidate archive hash and
clean-consumer provenance. Linux's complete Chromium suite passes 108 cases.
These are candidate artifacts, not registry or published-release installs.

## Qualification and publication gate

The candidate library and native CLI both identify as 0.3.0. Candidate checks
produce `_build/evidence/consumer-<platform>.json` and
`_build/evidence/tutorial-consumer-<platform>.json`; these explicitly identify
isolated candidate-cache provenance. Native archives retain SHA-256 files and
third-party licenses. Linux x64 and macOS arm64 qualification are required before
publication. PR CI runs both supported platforms, including clean packaged
consumers; Linux also runs the complete Chromium suite.

The existing Release candidate workflow defaults `publish` to false. Publication
requires an owner/admin's manual dispatch approving the exact 0.3.0 merge SHA and
merged release PR URL. Its script rejects a workstation, stale SHA, wrong version,
unmerged PR and default dry run. No publication dispatch is included in this work.
The implementation merge approval does not grant this separate release approval.

After the owner gate, record the actual Actions run, Mooncakes coordinate,
matching CLI archive URLs/checksums and clean published-consumer results. That
qualification must resolve the real registry and archives without candidate
caches or local overrides. Keep release story `telescope-58o.6`, the epic and the
OpenSpec change open until the publication-verification PR merges. Archive and
synchronize specs in that final PR. No downstream repository is migrated here.

# Telescope 0.5.1

The library is published as `moonrockz/telescope@0.5.1` on
[Mooncakes](https://mooncakes.io/docs/moonrockz/telescope), with a
[matching CLI release](https://github.com/moonrockz/telescope/releases/tag/v0.5.1).
Owner-approved [Actions run 40970873832](https://github.com/moonrockz/telescope/actions/runs/40970873832)
published exact source `1b0808634f9a173f6368e5e3b9ac6edde662dc16` after
[release PR 22](https://github.com/moonrockz/telescope/pull/22). The tag points
to that source. The live owner/admin gate checked the exact commit, version,
event inputs and merged release PR before upload.

## Windows behavior and compatibility

[Implementation PR 21](https://github.com/moonrockz/telescope/pull/21) repairs
native Windows drive and UNC canonical paths, including extended prefixes.
The host normalizes those paths before containment checks, joins and sibling
staging. Drive-root parents retain their root. POSIX filenames, authored
relative paths, source/symlink boundaries and staged promotion retain their
existing behavior. Public signatures and manifest version 1 remain compatible.
Moon-Lander retains its separate API-index content-link adapter.

The Windows native-library host is qualified. The CLI distributions remain
Linux x64 and macOS arm64; no Windows CLI archive is claimed. The upstream
compiler pin remains MoonBit `0.10.17+093cb8f9c`.

The release repeated qualification on the exact approved source. Windows passed
strict native checks and all 36 host tests, including contained file access,
source escapes, staged assembly and real loopback HTTP preview. Publication
requires that Windows result as well as the existing Linux/macOS distribution
qualifiers and credential preflight. Linux passed all 124 browser cases.

The credential-dependent dry run, library upload, matching CLI publication and
Linux public consumer succeeded in the Actions publication job. A separate
macOS public consumer also passed:

Both consumers started from empty public registry homes, installed the real
Mooncakes package and downloaded checksum-verified CLI archives. They used no
candidate cache, workspace/path override or consumer credential. Checks cover
host/CLI builds at root and nested bases, artifact bytes, custom providers,
